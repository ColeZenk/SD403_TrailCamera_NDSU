# Software Design Description 200
##  ESP32-DevKitV1 Main Controller -- Overview

---

## Overview

The ESP32-DevKitV1 is the central hub of the trail camera system. It receives raw image frames from the ESP32-CAM over SPI, forwards them to the Tang Nano 9K FPGA over a second SPI bus for WHT compression, receives compressed coefficients back from the FPGA, packages them into LoRa packets, and transmits over UART to the RYLR998 module. It also manages peripheral sensors (temperature/humidity), a stepper motor (via FPGA I2C GPIO expander), and an interrupt-driven PIR motion detector.

> **Hardware:** ESP32-DevKitV1 | No PSRAM | Dual SPI buses | UART to LoRa | I2C to FPGA

## Operating Modes

### Production Mode (default)
Five FreeRTOS tasks run concurrently:

| Task | Priority | Stack | Core | Purpose |
|------|----------|-------|------|---------|
| `cam_rx` | High | 4 KB | Any | Receive frames from ESP32-CAM over SPI |
| `img_proc` | Medium | 8 KB | Any | Process received frames, forward to FPGA |
| `lora_rx` | Medium | 4 KB | Any | Receive LoRa packets (commands from S3) |
| `sensors` | Low | 4 KB | Any | Periodic AHT20 temperature/humidity reads |
| `heap_mon` | (main) | — | 0 | Heap usage logging every 10s |

### LoRa Bench Mode (`#define TEST_MODE_LORA_BENCH`)
Only the `lora_bench` task runs. All camera, FPGA, and sensor initialization is skipped. Used for RF link validation with the S3 echo slave. See [SDD004](../../../Documentation/SDDs/SDD004.md) for full bench test protocol.

### Other Test Modes
- `TEST_MODE_FPGA_PATTERNS` — sends test patterns to FPGA over SPI
- `TEST_MODE_FPGA_GPIO` — exercises FPGA I2C GPIO expander
- `TEST_MODE_LORA_LOOPBACK` — local LoRa echo test
- Mutually exclusive (enforced by `#error` in `config.h`)

## Interprocessor Communication

### CAM → DevKitV1 (SPI Slave)
- DevKitV1 acts as SPI slave receiving frames from ESP32-CAM
- Frame protocol: 12-byte header (magic `0xCAFEBEEF`, size, checksum) + raw pixel data
- See SDD100 for transmit-side details

### DevKitV1 → FPGA (SPI Master)
- DevKitV1 acts as SPI master sending frames to Tang Nano 9K
- FPGA receives via `esp_interface.v` SPI slave
- **TODO:** Add SPI read transaction to receive compressed coefficients from FPGA (SOMI path, SDD401)

### DevKitV1 → LoRa (UART)
- RYLR998 module on UART2 (GPIO17 TX, GPIO16 RX) at 115200 baud
- AT command protocol: `AT+SEND=<dest>,<len>,<data>`
- Module address: 2 (sender), destination: 1 (S3 receiver)
- Network ID: 6 (must match S3)
- See SDD003 for link budget, SDD004 for AT protocol details

### DevKitV1 -- FPGA (I2C)
- I2C master on I2C port 0
- Communicates with FPGA's `i2c_gpio_expander.v` at address `0x27`
- Writes: stepper motor coil patterns (GPIO out bits [3:0])
- Reads: joystick button state (GPIO in bits [2:0])
- External 4.7k pull-ups on SDA/SCL

## Peripherals

### AHT20 Temperature/Humidity Sensor
- I2C address: `0x38`
- Polled periodically by `sensors_task`
- Data logged, available for environmental metadata

### PIR Motion Detector
- Interrupt-driven on GPIO 25
- ISR signals a semaphore, processed by main pipeline
- Triggers camera capture sequence

### Stepper Motor
- 4-wire unipolar stepper
- Driven via FPGA I2C GPIO expander (coils on gpio_out[3:0])
- Pan/tilt positioning for multi-position reference frame system
